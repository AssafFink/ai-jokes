# Architecture

> איך האפליקציה בנויה, במונחים פשוטים. אין צורך להיות מומחה — פשוט תעד את ההחלטות. Claude יכול לעזור לך למלא זאת ולהמליץ על אפשרויות אם אינך בטוח.

## 1. Tech stack
> הטכנולוגיות המרכזיות. אם אינך בטוח, בקש מ-Claude להמליץ על setup למתחילים.
- **סוג האפליקציה:** אתר (דף יחיד), דפדפן דסקטופ ומובייל
- **Frontend:** React + TypeScript, נבנה עם Vite. ללא framework נוסף.
- **Backend:** Node.js + TypeScript + Express. Route אחד: `POST /api/joke`.
- **Database:** אין. שום מסד נתונים ושום שמירה ב-Storage.
- **Hosting:** Render — Web Service יחיד המחובר ל-GitHub, auto-deploy בכל push.
- **אחסון קוד:** GitHub

## 2. נתונים (Data)
> איזה מידע האפליקציה שומרת. פשוט רשום את המודלים והפרטים שלהם — אין צורך ב-schema טכני.
- **אין מודלים ואין נתונים נשמרים.** הבדיחה נוצרת לפי דרישה, מוחזרת ללקוח ומוצגת. שום דבר לא נשמר בשרת, בלקוח או בכל Storage.
- **הודעה בין לקוח לשרת (זמנית בלבד):** בקשה `{ topic?: string }` → תשובה `{ joke: string }`.

## 3. אינטגרציות ושירותים
> שירותים חיצוניים שהאפליקציה מתחברת אליהם.
- **OpenAI API** — יצירת הבדיחה (מודל `gpt-4o-mini`) דרך חבילת `openai` הרשמית. הקריאה נעשית מהשרת בלבד; מפתח ה-API אינו חשוף ללקוח.
- אין ספק תשלום ואין שירותים חיצוניים נוספים.

## 4. Deployment (עלייה לאוויר)
- **Repo:** GitHub — jokes (monorepo יחיד עם `client/` ו-`server/`)
- **Hosting:** Render Web Service יחיד, מחובר ל-repo. Build בונה את הלקוח ומקמפל את השרת; Express מגיש בפרודקשן גם את `client/dist` וגם את `/api/joke`. משתנה סביבה: `OPENAI_API_KEY` (ו-`PORT` מסופק ע"י Render).
- הערה: Claude מכין את הקוד וה-config; **אתה** פותח את החשבונות, מדביק את המפתחות, ומאשר את ה-deploy.

## 5. החלטות מרכזיות (ADRs)
> תעד כאן כל החלטה משמעותית, כדי שהסיבה לא תאבד. רשומה קצרה אחת לכל החלטה. ADR = Architecture Decision Record.

### ADR-1: שירות יחיד ב-Render (Express מגיש גם את ה-React build)
- **הקשר:** צריך לארח לקוח React ושרת Express עם API אחד, בפשטות ובזול.
- **החלטה:** Web Service יחיד ב-Render. Express מגיש את `client/dist` וגם עונה ל-`/api/joke`.
- **השלכות:** מקל — כתובת אחת, בלי CORS, deploy אחד, זול יותר. נדחתה חלוקה לשני שירותים (Static Site + Web Service) שהייתה דורשת הגדרת CORS וכתובת API נפרדת.

### ADR-2: התאמת שפת הבדיחה נעשית בפרומפט
- **הקשר:** הבדיחה צריכה להיות בשפת הנושא שהוזן, ובעברית כשאין נושא.
- **החלטה:** ההוראה לשפה מוטמעת בפרומפט ל-OpenAI, ללא זיהוי שפה בקוד.
- **השלכות:** מקל — פשוט ומדויק מספיק. תלוי ביכולת המודל לזהות את שפת הנושא.

### ADR-3: ללא מסד נתונים / ללא Storage
- **הקשר:** הדרישה היא שדבר לא יישמר.
- **החלטה:** אין DB, אין קבצים, אין cache מתמשך; הבדיחה חולפת דרך הבקשה בלבד.
- **השלכות:** מקל — פשטות ופרטיות. אין היסטוריה או שחזור בדיחות (מחוץ לטווח ממילא).
